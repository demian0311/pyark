An offline Python dev world on Omarchy

Scripts that fill a store while online, then build a full Python workstation from that store with no network: toolchain, curated libraries, their docs, a local docs site, and a Python-ready nvim.

The problem

Omarchy gives you a finished desktop, but Python development on it assumes a live network at every step: uv fetches interpreters, pip fetches wheels, nvim's Mason fetches language servers, and every "how do I" is a browser tab. Lose the network and the machine is a text editor. There is no single place that says how to start a project here, which tools are blessed, or where the docs are.

The shape

harvestRuns online. Downloads Arch packages, Python builds, wheels, nvim plugins, language servers and HTML docs into the store.
→
store/A plain directory. Gitignored. Lives on this disk or a USB drive. Everything install needs, nothing else.
→
installRuns offline. Points pacman, uv and nvim at the store, builds the docs site, serves it on localhost.

Everything else is a consumer of the store: the docs site reads from it, pyark new scaffolds from a template in it, nvim loads plugins from it.

Repo layout

pyark/
├── bin/            pyark (one entry point: harvest · install · serve · new · doctor)
├── harvest/        one script per source: arch.sh  python.sh  wheels.sh  nvim.sh  docs.sh
├── install/        one script per target: arch.sh  python.sh  nvim.sh  site.sh
├── manifest/       what to fetch — packages.txt  arch.txt  docs.txt  nvim-plugins.txt
├── templates/      copier template for a new project (pyproject, ruff, pytest, justfile)
├── nvim/           LazyVim config layered on yours: python extra, store-backed plugin dir
├── site/           mkdocs source: your pages + generated index of harvested docs
├── mockups/        dated pages like this one
└── store/          gitignored · ~/.local/share/pyark or a USB mount

A day with it

  • pyark new invoices makes a project with a venv, ruff, pytest and a justfile, from the store, in under a second.
  • uv add polars resolves against the local wheelhouse. A package not in the manifest fails fast with "not in store".
  • pyark serve opens localhost:8800: your guides on the left, every harvested library's docs under one search.
  • nvim opens with completion, diagnostics and formatting on save. No download prompt, ever.
  • pyark doctor says what the store holds, what is stale, and what the last harvest skipped.

Options: where the docs live

The biggest UX decision. The store can hold docs in three forms.

🟢 recommended

mkdocs hub + raw HTML docs

localhost:8800 ├ Guides your pages ├ Python 3.14 docs.python.org zip ├ polars htmlzip from readthedocs ├ fastapi mkdocs build of the repo └ Search one index over all

One static server, one search. Your guides link straight into a library's page. Cost: each library needs a known way to get its HTML, and about a third will need a per-library rule.

🟡 viable

Zeal docsets

Zeal (GUI) ├ Python 3 ├ pandas └ Django (no custom pages)

Zeal, the offline docset browser, has instant search and a GUI. But it is a separate app, docsets exist for only the big libraries, and your own guides cannot live in it.

🔴 advise against

DevDocs mirror

devdocs/ ├ Ruby + thor scraper ├ per-library scrapers └ ~GBs

Beautiful and unified, but it drags a Ruby toolchain into the harvest and its scrapers break with each library release.

Options: type checker

🟢 recommended

ty or pyrefly

Single binary, no node. Both are young; the harvest keeps pyright as a fallback until one proves out on your code.

🟡 viable

basedpyright

Mature and what LazyVim expects, but it needs node, so node and its tarball join the store.

Open questions

  • Is the target this laptop when offline, or a second air-gapped machine? Both work with the store on a USB drive, but the second needs the store to carry Omarchy's own packages too.
  • Jupyter or marimo for notebooks, or neither? JupyterLab alone is a large slice of the store.
  • How much of your current LazyVim config is sacred? The nvim layer can be a few files added to it, or a separate config started with NVIM_APPNAME=pyark.
  • Store size budget. The manifest above lands near 3 to 6 GB without the heavy ones. With them, 15 GB or more.
